08 — Evaluación de BD

PostgreSQL vs DynamoDB vs Redis

Criterio PostgreSQL 15 ✓ DynamoDB Redis
Tipo Relacional ACID NoSQL key-value / doc In-memory key-value
JOINs Nativo No — requiere denorm. No
Consistencia ACID fuerte Eventual (configurable) Eventual
Escalado Vertical Horizontal automático Horizontal
ORM / JPA Spring Data JPA nativo Integración manual No aplica
¿Por qué no? — Elegido ✓ Denorm. costosa con datos relacionales Quota sandbox; JWT elimina sesiones
Conclusión: Para un e-commerce con relaciones User→Order→Item→Product e integridad referencial, PostgreSQL es la elección natural con JPA. DynamoDB brillaría con millones de lecturas simples de productos. Redis complementaría en producción real como caché de catálogo.

13 — Auto Scaling

Auto Scaling en acción

Política — CPU Target Tracking

Scale-Out
CPU > 50% sostenido → ASG lanza t2.medium
Cooldown: 300 segundos
Scale-In
CPU < 50% por 5 min → termina instancia extra
Protege la instancia original

Stress Test

# stress-test.sh — ProxyJump via Bastion ssh -J ec2-user@{bastion-ip} \ ec2-user@{ec2-private-ip} \ "stress --cpu 2 --timeout 300s" # Verificar nuevo nodo aws autoscaling describe-auto-scaling-groups \ --auto-scaling-group-names ecom-asg-prod

16 — Retos

Retos y limitaciones del sandbox

IAM Read-Only
Problema: No crear roles IAM
Solución: Usar LabInstanceProfile existente del sandbox
RDS Sin Multi-AZ
Problema: Sandbox no soporta Multi-AZ
Solución: Single-AZ con backups de 7 días
CloudTrail Bloqueado
Problema: Sandbox bloquea CreateTrail
Solución: Stack deshabilitado; CT nativo de sandbox activo
SSH a EC2 Privadas
Problema: EC2 en subredes privadas, sin IP pública
Solución: ProxyJump via Bastion + ssh-agent forwarding
Credenciales AWS Academy
Problema: Expiran cada 4 horas
Solución: Script set-aws-session.sh renueva sesión
Spring Boot necesita RAM
Problema: t2.micro insuficiente para JVM
Solución: t2.medium (4 GB RAM) — estable y confiable
